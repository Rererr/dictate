# ローカル LLM で整形する（はじめての人向け）

Dictate の「LLM で整える（句読点）」は、話した文の句読点と空白を整える任意の機能である。
フィラー（「えっと」「えー」「あのー」「あの、」など）は LLM なしで規則が消し、LLM には任せない。
この文書は、ローカル LLM を触ったことがない人が、この機能を動かすところまでを扱う。
Dictate 自体はローカル LLM なしで動くので、要らなければ読まなくてよい。

## ローカル LLM とは何か

**ローカル LLM** は、ChatGPT のような言語モデルを、クラウドではなく手元の Mac の中で動かすものである。
話した内容は Mac の外に出ず、使用料もかからない。
代わりに、モデルのファイル（数 GB）をダウンロードし、動かしている間はメモリを使う。

Dictate は、モデルを自分の中に抱え込まない。
別のプログラム（**サーバ**）がモデルを読み込んで待ち受け、Dictate は発話のたびにそのサーバへ文を送って結果を受け取る。
サーバは OpenAI の API と同じ形式で話せるものなら何でもよく、この文書では Apple Silicon 向けに作られた mlx-lm を使う。

## Dictate が LLM に任せている範囲

LLM に任せるのは、句読点と空白の変更だけである。
言い直しの反映、箇条書きへの変換、数値や単位の補完は任せない。
フィラーは LLM に送る前に規則が消す。LLM がフィラーを消した出力は検証が捨てる（「フィラーを消す」を切った発話でもフィラーが残る）。作者の履歴で測ると、規則の後で LLM がフィラーに効いた発話は無かった（下の「規則の後段で測る」）。
数値は LLM に見せる前に印に置き換え、戻すときに元の数値に戻す。
LLM の出力は「句読点と空白の変更だけでできているか」を検証し、通らなければ捨てて整形前の文を挿入する。

範囲をここまで絞るのは、試した結果による（後述の「モデルをどう選んだか」）。
予算の 1 秒に入る大きさのモデルは、編集の指示を無視したり、発話にない単位を補ったりした。
禁止の文言をプロンプトに足しても止まらなかったので、出力の側を構造で縛っている。

## 必要なもの

- Apple Silicon の Mac で、メモリ 16 GB 以上。8 GB の Mac では、既定のモデル（Qwen3.5-4B の 4bit 版、動作中に約 3.5 GB）でもスワップに入って遅くなるので、Dictate は LLM 整形をオンにできない（GPU に使えるメモリが 10 GB 未満を基準にする）。16 GB は未計測で、遅ければ温めの後に知らせる
- ディスクの空き 4 GB（既定の 4B は約 3 GB）
- Homebrew。無ければ https://brew.sh の手順で入れる
- 初回だけインターネット接続。モデルのダウンロードに使う（以後は不要）

## 手順

### 1. サーバを入れる

```sh
brew install mlx-lm
```

`mlx_lm.server` というコマンドが入る。
`which mlx_lm.server` で場所が出れば済んでいる。

### 2. 一度、手で起動してモデルを取る

```sh
mlx_lm.server --model mlx-community/Qwen3.5-4B-MLX-4bit --port 8124 --chat-template-args '{"enable_thinking": false}'
```

初回はモデルのダウンロードが始まり、回線によって数分かかる（M2 の Air で約 4 分。以前の既定の Qwen3-4B、約 2.3 GB での値）。
ダウンロードは `~/.cache/huggingface/` に残り、二度目からは要らない。
`Starting httpd at 127.0.0.1 on port 8124` のような行が出たら待ち受けに入っている。

別のターミナルで次を打ち、モデル名を含む JSON が返れば動いている。

```sh
curl http://127.0.0.1:8124/v1/models
```

確かめたら、サーバのターミナルで Ctrl+C を押して止めてよい。
次からは Dictate が起動する。
この手順を飛ばして、いきなり手順 4 でオンにしても構わない。その場合は Dictate がこのコマンドで起動し、ダウンロードも始まる。

各引数の意味は次のとおり。

- `--model`: Hugging Face 上のモデルの名前。mlx-community が MLX 向けに変換して配っている
- `--port 8124`: Dictate の既定の接続先。他のポートにするなら `config.json` の `formatter.endpoint` も合わせる
- `--chat-template-args '{"enable_thinking": false}'`: Qwen3 と Qwen3.5 の「考えてから答える」動作を止める。Qwen3.5-4B のテンプレートは既定で考えてから答え、この指定のときだけ考える段を空にする。付けないと結果が遅くなり、予算の 1 秒に入らない

### 3. 起動コマンドを確かめる

Dictate は、オンにしたときに接続できなければ `formatter.startCommand` のコマンドでサーバを起動する。
既定値が手順 2 と同じコマンドなので、mlx-lm を既定のモデルとポートで使うなら、何も書かなくてよい。

別のモデルやポートにするときは、メニューバーのマイクのアイコンから「設定ファイルを開く」を選び、`formatter.startCommand` を書き換える。

```json
"formatter" : {
  "enabled" : true,
  "startCommand" : "mlx_lm.server --model mlx-community/Qwen3.5-4B-MLX-4bit --port 8124 --chat-template-args '{\"enable_thinking\": false}'",
  ...
}
```

JSON の文字列の中なので、`"` は `\"` と書く。
自動で起動してほしくなければ `""`（空文字）にする。`null` は既定のコマンドの意味になる。
保存したら、メニューの「設定と辞書を再読み込み」を選ぶ。

### 4. オンにする

メニューの「LLM で整える（句読点）」をオンにする。
接続できなければ、Dictate が `startCommand` のコマンドでサーバを起動し、「整形サーバを起動しています」と知らせる。
待ち受けが開いた時点で「接続できました。モデルを読み込んでいます」と出る（手元では 3 秒）。
mlx-lm は待ち受けを先に開き、モデルは背景で読み込む。読み込みが終わるまで Dictate は整形を試みず、発話はそのまま入る。
初回でモデルのダウンロードが残っていれば、終わるまで同じ状態が続く。進み具合はメニューの「整形サーバのログを開く」で見られる。
読み込みが終わると「整形の準備ができました」と出て、次の発話から整形が効く。

メニューを開くと「整形: 有効（接続可。整形に 0.5 秒）」のように、接続の状態と温めた直後に測った所要が出る。
「サーバを起動中 N 秒」「モデルを読み込み中 N 秒」の間は、まだ待っている。

サーバは、「LLM で整える」をオフにしたときと、Dictate を終了したときに、Dictate が止める。
Dictate が強制終了されたときも、サーバ側が親の消失を見て 1 秒以内に止まる。
Dictate が起動したものだけを止め、自分で立てたサーバには触らない。

mlx-lm が入っていなければ、起動せずに「整形サーバの mlx-lm が入っていません。ターミナルで brew install mlx-lm を実行してから」と知らせる。
`startCommand` を `""` にした場合は、サーバを自分で起動してからオンにする。
接続できないときは、その旨と対処をトーストで知らせ、メニューに「ローカル LLM の手引きを開く」が出る。

## 動いているかを確かめる

話した後の挿入で句読点が整っていれば動いている（フィラーは LLM なしでも規則で消えるので、目印にならない）。
メニューの「整形」の行が「有効（接続可。整形に N 秒）」になっていることでも分かる。
履歴（`~/Library/Application Support/Dictate/history.jsonl`）には、整形前の文、整形後の文、採用の可否、かかった時間が残る。

## モデルをどう選んだか

既定は Qwen3.5-4B の 4bit 版である。
4B を既定にした決め手は「キーを離してから 1 秒以内に挿入する」という予算に入るかで、Mac によって違う（下の「2 台での比較」。当時の 4B は Qwen3-4B）。
4B を Qwen3-4B から Qwen3.5-4B に替えたのは、2026-11-16 の比較による（下の「8 モデルの比較」）。Qwen3.5-4B は M2 の Air では測っていない。
最初の計測は作者 1 人の声と 1 台の Mac（M4 Pro、メモリ 48 GB、macOS 27）によるもので、整形の 4 文（Slack 風、メール風、メモ風、介護記録風）に同じプロンプトを与えた。

| モデル | 整形の所要（4 文） | 分かったこと |
|---|---|---|
| Qwen3.8-27B 6bit（vMLX） | 2.8〜7.1 秒 | 整形の品質は使える水準。ただし言い直しを半分だけ反映し、「150」に発話にない「ml」を補った。音声入力には遅すぎる |
| Qwen3-8B 4bit（mlx_lm.server） | 0.36〜0.94 秒（温まった状態。初回は 0.6〜1.3 秒） | 予算に入る。ただし「箇条書きにして」の指示を無視し、文の一部を落とすことがあり、「150」に「ミリリットル」を補った |
| Qwen3-1.7B 4bit、Qwen3-0.6B 4bit | 0.20 秒、0.14 秒（中央値。下の表） | 速いがフィラーをほぼ消さずに返す。別の用途（辞書の候補を選ぶ採点器）でも、実機の 99 発話で 8B は直す 7 件・壊す 0 件、1.7B は直す 1 件・壊す 0 件、0.6B は直す 1 件・壊す 2 件で、小さくするほど判断が落ちる |
| Qwen3.5-4B、Gemma 4 E4B | この 4 文では未計測 | 句読点と空白の役割では 2026-11-16 に測った（下の「8 モデルの比較」） |

27B は品質が良くても遅延で落ち、8B は遅延に入っても指示追従と補完に問題が残った。
この結果から、LLM の役割を「フィラーの削除と句読点」に絞り、編集の指示はコードで扱い、数値は印に置き換えて LLM に見せない設計にした。その後、フィラーの削除は語彙の規則だけで行うことにし（設計書の ADR-14）、作者の履歴での計測を経て LLM の役割は「句読点と空白」に絞り、プロンプトと検証からフィラーを外した（下の「規則の後段で測る」）。下の表の「効果」は、当時のプロンプト（フィラーの除去を頼む）での値である。
どのモデルでも、検証を通った出力だけを使うので、文が勝手に書き換わることはない。

4B より小さいモデル（1.7B 以下）は速いがフィラーを消さないので使わない（下の表）。
8B より大きいモデルに替えるなら、`formatter.budgetSeconds` を延ばす。
予算を超えた結果は挿入されず、履歴にだけ残る。

### 自分の Mac で測る

`eval/formatter_bench.py` が、12 文（文頭のフィラーは規則と同じく落としてから）をサーバに送り、温まった状態の所要と採用率（アプリの検証と同じ判定）を出す。
モデルを替えて比べるときは、サーバをそのモデルで立ててから走らせる。

```sh
mlx_lm.server --model mlx-community/Qwen3.5-4B-MLX-4bit --port 8124 --chat-template-args '{"enable_thinking": false}'
python3 eval/formatter_bench.py --model mlx-community/Qwen3.5-4B-MLX-4bit
```

「採用」は検証を通る割合で、句読点と空白以外を変えた出力（フィラーの削除を含む）は棄却になる。
下の表の「効果」の列は、フィラーの除去を頼んでいた当時のプロンプトでの値で、いまのスクリプトは出さない。

句読点を置いた位置が正解と合うかは、`eval/punct_bench.py` で見る。
同じ 12 文を送って出力を JSON に残し（`collect`）、正解の `eval/punct_reference.tsv` と照合する（`score`）。
正解を直したときは、サーバなしで採点だけやり直せる。
接続先の既定は 8131 番ポートなので、上の 8124 番のサーバに送るときは `--endpoint` を付ける。

```sh
python3 eval/punct_bench.py collect --model mlx-community/Qwen3.5-4B-MLX-4bit --endpoint http://127.0.0.1:8124/v1 --out punct-outputs.json
python3 eval/punct_bench.py score punct-outputs.json --detail
```

作者の Mac mini（Apple Silicon、メモリ 48 GB）での結果（2026-10-10、同じプロンプト、12 文のうちフィラーのある文は 8）:

| モデル | 所要の中央値 | 最大 | 採用 | 効果 | 備考 |
|---|---|---|---|---|---|
| Qwen3-8B 4bit | 0.47 秒 | 0.81 秒 | 9/12 | 7/8 | 棄却の 3 件は「を」の補い、「確認し」への言い換え、「了解です」の脱落。どれも検証が捨てて整形前の文が入る |
| Qwen3-1.7B 4bit | 0.20 秒 | 0.29 秒 | 11/12 | 1/8 | 速いが、フィラーをほぼ消さずにそのまま返す。採用が高いのはそのため |
| Qwen3-0.6B 4bit | 0.14 秒 | 0.17 秒 | 8/12 | 0/8 | フィラーを消さず、語の脱落や誤字もある |

#### 2 台での比較（2026-10-10、同じ 12 文。モデルはどれも Qwen3）

| Mac | モデル | 所要の中央値 | 最大 | 予算 1 秒以内 | 効果 |
|---|---|---|---|---|---|
| Mac mini（M4 Pro、48 GB） | 8B | 0.47 秒 | 0.81 秒 | 12/12 | 7/8 |
| MacBook Air（M2、24 GB） | 8B | 1.20 秒 | 2.15 秒 | 1/12 | （消せるが間に合わない） |
| MacBook Air（M2、24 GB） | 4B | 0.71 秒 | 1.24 秒 | 11/12 | フィラーのある 8 文で消した（件数の記録は無い）。数値の印を 5 文中 2 文で壊し、検証が捨てた |
| MacBook Air（M2、24 GB） | 1.7B | 0.36 秒 | 0.60 秒 | 12/12 | 7 文でフィラーを消さず返す |

4B は M2 の Air でも予算に入り、フィラーを消す。弱点は数値の印で、壊した出力は検証が捨てて整形前の文が入る（数値が壊れて入ることはない）。
8B は数値の印を保つが、M2 では予算に入らない。
そこで 4B を既定にし、温めの直後の計測で 4B が予算の 4 割以下なら、メニューに「整形モデルを 8B に上げる」を出すことにした（2026-11-16 の比較を受けて、2026-11-20 にやめた。下の「8 モデルの比較」）。
1.7B 以下はフィラーを消さずに返すので、速くても使わない。
既定の 4B は、その後 Qwen3.5-4B に替えた（下の「8 モデルの比較」）。上の Air の値はどれも Qwen3 のもので、Qwen3.5-4B は Air では測っていない。

上の表はどれも、フィラーの規則を通す前の文を送っている。アプリでは規則がフィラーを消してから LLM に送るので、LLM の実際の仕事は次の計測で見る。

#### 規則の後段で測る（2026-10-11）

`Tests/DictateKitTests/FormatterSecondStageBench.swift` が、自分の履歴（`history.jsonl`）の発話を、規則を通す前と後の 2 条件で LLM に送り、アプリと同じ検証で採否を取って件数だけを出す（本文は出力しない）。
測るモデルは `DICTATE_LLM_BENCH_MODELS`（カンマ区切り）で選ぶ。指定が無ければ既定の 4B と 8B（Qwen3.5-4B と Qwen3-8B）を測る。
採用で本文が変わった発話は、句読点と空白の増減を境目ごとに数える。
`DICTATE_LLM_BENCH_JSON` に書き出し先を指定すると、件数と発話ごとの所要（本文は含まない）を JSON でも残す。
サーバは既定で 8131 番ポートのものを使い（`DICTATE_LLM_BENCH_ENDPOINT` で変えられる）、動作中の Dictate のサーバには触らない。

```sh
mlx_lm.server --model mlx-community/Qwen3.5-4B-MLX-4bit --port 8131 --chat-template-args '{"enable_thinking": false}'
DICTATE_LLM_BENCH=1 DICTATE_LLM_BENCH_MODELS=mlx-community/Qwen3.5-4B-MLX-4bit DICTATE_LLM_BENCH_JSON=bench.json \
  swift test --filter 整形の二段目の実測 -Xswiftc -plugin-path -Xswiftc "$(xcode-select -p)/usr/lib/swift/host/plugins/testing"
```

mlx_lm.server は要求されたモデルを取得して読み込む。
サーバを立てたときと違うモデルを指定すると、手元に無ければダウンロードが始まる（8B は約 4.3 GB）。

2026-10-11 に、作者の Mac mini（M4 Pro、48 GB）、履歴 136 発話（本文が空の 10 件を除く）で、Qwen3-4B と Qwen3-8B を測った結果:

| 条件 | モデル | 採用 | 棄却 | 採用で消えたフィラーの出現数 | 句読点と空白だけ変わった発話 | 所要の中央値 |
|---|---|---|---|---|---|---|
| 規則の前 | 4B | 94/136 | 42 | 3 | 17 | 0.33 秒 |
| 規則の後（アプリの条件） | 4B | 93/136 | 43 | 0 | 17 | 0.33 秒 |
| 規則の前 | 8B | 111/136 | 25 | 4 | 11 | 0.49 秒 |
| 規則の後（アプリの条件） | 8B | 110/136 | 26 | 0 | 12 | 0.49 秒 |

履歴に語彙のフィラーは 4 回しか出ておらず、規則が 4 回とも消す。
規則の後で LLM がフィラーを消した発話は無く、効いたのは句読点と空白の変更が 136 件中 12〜17 件である。
この結果から、LLM 整形の役割を「句読点と空白」に改めた。

役割を改めた後、組み込みのプロンプトからフィラーの指示を外し、検証もフィラーの削除を認めない形にした（設計書の ADR-6、ADR-14）。
同じ 136 発話で測り直すと、規則の後の条件で棄却は 4B が 43 → 15 件、8B が 26 → 19 件に減り、句読点と空白が変わった発話は 4B が 17 → 28 件、8B が 12 → 35 件に増えた。
所要の中央値は変わらない。上の表は外す前の値である。

#### 8 モデルの比較（2026-11-16）

規則の後段の計測と、12 文の正解との照合を、8 モデルに同じ条件でかけた。
Mac は作者の Mac mini（M4 Pro、48 GB）、サーバは mlx-lm 0.32.2 で、要求はアプリの既定（temperature 0、思考を止める指定あり）と同じにした。

| Qwen3-8B 4bit | 192 | 182 | 0.49 秒 | 4/12 | 0.67 | 1.00 | 32/80 | 5.2 GB |
| Qwen3.5-2B 4bit | 208 | 208 | 0.13 秒 | 3/12 | 0.58 | 1.00 | 29/43 | 1.8 GB |
| Qwen3-1.7B 4bit | 198 | 198 | 0.14 秒 | 2/12 | 0.33 | 1.00 | 13/16 | 1.6 GB |

| Gemma 4 E2B 4bit | 205 | 205 | 0.12 秒 | 1/12 | 0.17 | 0.63 | 172/174 | 3.1 GB |

「採用」は検証を通った発話、「採用かつ 1 秒以内」は実際に挿入される発話の数である。
12 文の 3 列は `eval/punct_bench.py` で正解と照合した値で、検証を通らなかった文は整形前の文のまま採点する。LLM を通さないと、完全一致 0/12、文中の句読点の再現率 0.25、空白の再現率 1.00 になる。
正解の文末は、問いかけを「？」にしている。問いかけの 3 文を「。」にした正解で採点すると、Qwen3.5-4B の完全一致は 9/12 になり、他のモデルは 6/12 以下だった。
「方針に反した発話」は、採用で本文が変わった発話のうち、正解の方針（空白は入力のまま残し、句読点を置いた所だけ消す。文末の句読点は消さない）に反する変更を含むものの数で、機械的に判定した。
動作中のメモリは、サーバのプロセスの phys_footprint である。

Qwen3.5-4B は、採用も挿入される発話も最も多く、文中の句読点の再現率も最も高い。所要は以前の既定の Qwen3-4B と同程度である。
この結果から、既定の 4B を Qwen3-4B から Qwen3.5-4B に替えた。
弱点は空白で、英数字の隣の半角空白を入力から消したり足したりする。方針に反した 52 発話の反した変更は、どれもこの空白だった（消した所が 54、足した所が 27）。
Qwen3-8B は採用と所要のどちらでも Qwen3.5-4B に及ばない。方針に反した発話は 8B の方が少ない（32 対 52）が、8B も履歴では半角空白を足す（51 か所。うち英数字の隣が 50）。12 文では、8B は空白を変えなかった。
この結果から、8B に上げる提案（メニューの項目と一度だけの通知）はやめた。モデルと起動コマンドが 8B の既定の組の人（以前の版で 8B に上げた人や、手で 8B にした人）には、予算に入らないときだけ「整形モデルを 4B に替える」を出す。
文中に読点を足した変更が正しいかは、履歴に正解が無いので判定していない。

この比較には、次の限界がある。

- M2 の MacBook Air では測っていない。4B を既定にした根拠は、Air での所要（Qwen3-4B で中央値 0.71 秒）だった。Qwen3.5-4B は M4 Pro では Qwen3-4B と同程度の速さだが、ファイルは約 3.1 GB（Qwen3-4B は約 2.3 GB）、動作中のメモリは約 3.5 GB（同 3.0 GB）と大きく、Air で予算に入るかは確かめていない。入らなければ、温めの後の計測が知らせる
- Mac は 1 台、履歴は作者 1 人のものである。履歴の採否の件数は、どのモデルも同じ日に測り直して変わらなかった（Qwen3.5-4B は負荷なしの 5 回とも採用 215 で、所要の中央値は 0.258〜0.261 秒）。12 文は 1 回だけ測った（各文を 2 回送り、2 回目の出力を使う）
- 同じ Mac で別のローカル LLM（Ollama の gemma4:26b-a4b）を間を空けずに呼び続けた負荷の下では、Qwen3.5-4B が規則の後で 1 秒以内に返した発話は 221 件中 220 件から 204 件に減った（gemma4:e4b の負荷では 207 件）。負荷の下は各 1 回だけ測った

以前の版でメニューから設定を変えたこと（切り替えの項目、ホットキーの登録、「設定ファイルを開く」）があれば、`config.json` に全項目が書き出されていて、以前の既定の Qwen3-4B が入っている。
新しい版を初めて起動したとき、Dictate はこの設定を一度だけ確かめる。
モデルと起動コマンドが以前の既定の組のまま（`formatter.model` が `mlx-community/Qwen3-4B-4bit` で、`formatter.startCommand` がそれを立てる既定のコマンド）で、接続先がこの Mac なら、2 か所を Qwen3.5-4B の組に書き換えて `config.json` に書き戻す。
書き換えたことはトーストで知らせ、その起動の間はメニューの状態の行にも出す（起動直後のトーストは、整形サーバの知らせにすぐ置き換わることがある）。
モデルか起動コマンドを自分で変えていた設定、起動コマンドを空にした設定、この Mac 以外の接続先、8B の組には触らない。

確かめるのは一度きりで、確かめたら設定と同じ場所に印のファイル（`formatter-model-migrated-from-qwen3-4b.txt`）を置く。
Qwen3-4B に戻すなら、同じ 2 か所のモデル名を `mlx-community/Qwen3-4B-4bit` にする。印がある間は、戻した設定を書き換えない。印を消すと、次の起動で確かめ直す。
設定が読めずに確かめられなかったとき（書式の誤りなど）と、書き戻せなかったときは印を付けず、次の起動で確かめ直す。
設定ファイルが無ければ、何も作らず、印も付けない。そのため、新しい版から使い始めた後に Qwen3-4B の組を手で書いた設定も、次の起動で一度だけ書き換えて知らせる（戻せば、二度とは書き換えない）。
書き戻した設定には今の版の項目（`apiKey`、`recognizer`）が加わるので、v0.2.0 では読めなくなる（メニューで切り替えたときも同じ）。
Qwen3.5 を読めるのは mlx-lm 0.30.7（2026-02-12）以降で、作者は 0.32.2 で測った。古い mlx-lm のままだと整形サーバの起動に失敗するので、`brew upgrade mlx-lm` を実行する。

## 別のサーバを使う

OpenAI 互換の API（`/v1/chat/completions`）を持つサーバなら、`config.json` の `formatter.endpoint` と `formatter.model` を変えれば使えるはずである。
Ollama や LM Studio がこれに当たるが、作者は試していない。
`enableThinking` の指定は Qwen3 と Qwen3.5 向けで、他のモデルでは無視されるか、エラーになる。`null` にすると送らない。
`http://` で繋がるのは、この Mac、IP アドレス、`.local` のホストまで（App Transport Security）。それ以外は `https://` にする。

## オンラインの API を使う（Claude など）

整形の接続先は、オンラインの OpenAI 互換 API にもできる（設計書の ADR-16）。
この Mac で LLM 整形を使えない（GPU に使えるメモリが 10 GB 未満）ときや、サーバもモデルも入れたくないときの選択肢である。
任せる範囲は変わらず、句読点と空白だけで、検証も同じである。賢いモデルを選んでも、許す変更は増えない。

話した本文（数値は印に置き換えたもの）がそのホストに送られる。
オンにしたときにトーストで知らせ、メニューの「整形」の行に「送信先 api.anthropic.com」のように出る。
履歴にはこれまでどおり整形前後の本文が残る。

Claude の例（鍵は [Claude API の設定](https://platform.claude.com/settings/keys) で作る。複数のワークスペースにまたがる鍵は `anthropic-workspace-id` ヘッダを求めるが、Dictate は送らないので、ワークスペースに閉じた鍵を使う）:

```json
"formatter": {
  "enabled": true,
  "endpoint": "https://api.anthropic.com/v1",
  "model": "claude-haiku-5-5",
  "apiKey": "sk-ant-...",
  "temperature": null,
  "enableThinking": null
}
```

- `apiKey` は `Authorization: Bearer` で送る。`config.json` は、アプリが書くときに本人だけが読める権限（0600）になる
- `temperature` は `null`（送らない）にする。Claude の 4.7 以降は 1 未満を 400 で拒む
- `enableThinking` も `null`（送らない）にする。Qwen3 と Qwen3.5 向けの項目で、知らない項目を拒む API がある（Claude は無視する）
- 接続先がこの Mac でないときは、`startCommand` は使わず、GPU メモリの判定もせず、8B から 4B への切り替えも出ない。この Mac で起動していたサーバは止める
- 鍵やモデル名が違うと、温めの要求（または発話の整形）が 4xx で拒まれ、理由（サーバの `error.message`）をトーストとメニューに出して止まる。直して「設定と辞書を再読み込み」を選ぶ。レート制限（429）は拒否に数えず、次の発話でまた試みる
- 有効にした（または有効のまま起動した）ときに「本文が … に送られます」と一度知らせる。直後の別の知らせに置き換わることがあるが、送信先はメニューの行に残る
- 費用は Haiku 5.5 で入力 100 万トークン $0.10、出力 $0.50（2026-10-16 時点）。1 発話は 200 トークン程度で、無視できる

予算の 1 秒に入るかは、作者は測っていない（手元に鍵が無かった）。
オンにすると温めの直後に 1 文を測り、メニューの「整形」の行に所要が出る。入らなければ `budgetSeconds` を延ばす。
12 文でまとめて測るには、`eval/formatter_bench.py` に鍵を渡す:

```sh
python3 eval/formatter_bench.py --endpoint https://api.anthropic.com/v1 --model claude-haiku-5-5 --api-key "$ANTHROPIC_API_KEY"
```

Claude 5 系は、互換 API 経由でも思考が既定でオンである。所要への影響は未計測。

## 困ったとき

| 症状 | 見るところ |
|---|---|
| 「整形サーバのコマンド「X」が見つかりません」「整形サーバの mlx-lm が入っていません」と出る | 起動前に、ログインシェルで `startCommand` の先頭の語を探して見つからなかった。入れてあるのに出るなら、`.zshrc` だけで PATH を足している環境なので、`startCommand` を `which mlx_lm.server` のフルパスにする。直したら「設定と辞書を再読み込み」の後に「整形サーバを起動」を選ぶ |
| 「整形サーバの起動に失敗（終了コード N）」と出る | 起動はしたが、すぐに終わった。メニューの「整形サーバのログを開く」で末尾を見る。引数の誤りや、モデル名の打ち間違いが多い |
| 「整形サーバを起動できませんでした」と出る | ログを作れないか、シェル自体を起動できない。括弧の中の理由を見る |
| 「待ち受けが 60 秒たっても開きません」と出る | サーバは動いているのに Dictate が見ているポートと違う。`startCommand` の `--port` と `formatter.endpoint` を揃え、「整形サーバを起動」を選ぶ |
| 「接続できました。モデルを読み込んでいます」のまま長い | ダウンロードの途中。ログに進み具合が出る。終わると「整形の準備ができました」と出る |
| 「サーバが動作中に終了」と出る | サーバが落ちた。ログの末尾に理由が出る。メモリ不足が多い。「整形サーバを起動」で起動し直せる |
| `Address already in use` | 同じポートで別のサーバが動いている。手で立てたものが残っていれば、そのターミナルで止める |
| 「整形に N 秒かかり、予算の 1.0 秒に入りません」と出る | 温めた直後に 1 文を測った結果。8B ならメニューの「整形モデルを 4B に替える」を選ぶ。4B でも入らないなら、`budgetSeconds` を N より少し長くする（キーを離してから入るまでがその分遅れる）か、整形をオフにする。メニューの「整形」の行にも所要が出る |
| 整形が採用されず「整形前の文を挿入しました」が続く | 時間切れなら `budgetSeconds` を延ばす。検証の棄却なら、モデルが句読点と空白（と語彙のフィラー）以外を書き換えている。作者の履歴（2026-11-16、221 発話、規則の後）では、Qwen3.5-4B が 6 件、Qwen3-8B が 29 件棄却された。履歴（`history.jsonl` の `"type": "format"` の行）に秒数と整形後の文が残る |
| 「整形サーバから結果を得られなかった」と出た後、メニューが「接続不可」になる | サーバが途中で落ちたか、応答しなくなった。Dictate が起動したものが落ちたなら「整形サーバが動作中に終了」も出て、メニューの「整形サーバを起動」で起動し直せる。動作中のまま応答しないなら「整形サーバを起動し直す」を選ぶ。自分で立てたサーバなら立て直して「設定と辞書を再読み込み」を選ぶ |
| 「整形サーバが HTTP 400 を返しました（…）」のように出て、メニューの「整形」の行も同じ理由になる | 要求の側の誤り（4xx）。鍵、モデル名、`temperature`（Claude なら `null`）、`endpoint` の末尾の `/v1` を確かめ、「設定と辞書を再読み込み」を選ぶ。括弧の中はサーバの `error.message` |
| 「整形の接続先 X に接続できません」と出る | 接続先がこの Mac でないので、Dictate はサーバを起動しない。ネットワークと `endpoint` を確かめる |
| Mac が重い | サーバがメモリを使っている（4B で約 3.5 GB、8B で約 4.6 GB）。使わないときは「LLM で整える」をオフにすると、Dictate が止める |
