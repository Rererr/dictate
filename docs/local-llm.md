# ローカル LLM で整形する（はじめての人向け）

Dictate の「LLM で整える」は、話した文からフィラー（「えっと」「あのー」）を消し、句読点を整える任意の機能である。
この文書は、ローカル LLM を触ったことがない人が、この機能を動かすところまでを扱う。
Dictate 自体はローカル LLM なしで動くので、要らなければ読まなくてよい。

## ローカル LLM とは何か

**ローカル LLM** は、ChatGPT のような言語モデルを、クラウドではなく手元の Mac の中で動かすものである。
話した内容は Mac の外に出ず、使用料もかからない。
代わりに、モデルのファイル（数 GB）をダウンロードし、動かしている間はメモリを使う。

Dictate は、モデルを自分の中に抱え込まない。
別のプログラム（**サーバ**）がモデルを読み込んで待ち受け、Dictate は発話のたびにそのサーバへ文を送って結果を受け取る。
サーバは OpenAI の API と同じ形式で話せるものなら何でもよく、この文書では Apple Silicon 向けに作られた mlx-lm を使う。

## Dictate が LLM に任せている範囲

LLM に任せるのは、フィラーの削除と句読点の変更だけである。
言い直しの反映、箇条書きへの変換、数値や単位の補完は任せない。
数値は LLM に見せる前に印に置き換え、戻すときに元の数値に戻す。
LLM の出力は「フィラーの削除と句読点の変更だけでできているか」を検証し、通らなければ捨てて整形前の文を挿入する。

範囲をここまで絞るのは、試した結果による（後述の「モデルをどう選んだか」）。
予算の 1 秒に入る大きさのモデルは、編集の指示を無視したり、発話にない単位を補ったりした。
禁止の文言をプロンプトに足しても止まらなかったので、出力の側を構造で縛っている。

## 必要なもの

- Apple Silicon の Mac。メモリは 16 GB 以上を勧める。既定のモデル（Qwen3-8B の 4bit 版）は動作中に約 4.6 GB を使う
- ディスクの空き 5 GB。モデルのファイルは約 4.3 GB
- Homebrew。無ければ https://brew.sh の手順で入れる
- 初回だけインターネット接続。モデルのダウンロードに使う（以後は不要）

## 手順

### 1. サーバを入れる

```sh
brew install mlx-lm
```

`mlx_lm.server` というコマンドが入る。
`which mlx_lm.server` で場所が出れば済んでいる。

### 2. 一度、手で起動してモデルを取る

```sh
mlx_lm.server --model mlx-community/Qwen3-8B-4bit --port 8124 --chat-template-args '{"enable_thinking": false}'
```

初回はモデルのダウンロードが始まり、回線によって数分から数十分かかる。
ダウンロードは `~/.cache/huggingface/` に残り、二度目からは要らない。
`Starting httpd at 127.0.0.1 on port 8124` のような行が出たら待ち受けに入っている。

別のターミナルで次を打ち、モデル名を含む JSON が返れば動いている。

```sh
curl http://127.0.0.1:8124/v1/models
```

確かめたら、サーバのターミナルで Ctrl+C を押して止めてよい。
次からは Dictate が起動する。
この手順を飛ばして、いきなり手順 4 でオンにしても構わない。その場合は Dictate がこのコマンドで起動し、ダウンロードも始まる。

各引数の意味は次のとおり。

- `--model`: Hugging Face 上のモデルの名前。mlx-community が MLX 向けに変換して配っている
- `--port 8124`: Dictate の既定の接続先。他のポートにするなら `config.json` の `formatter.endpoint` も合わせる
- `--chat-template-args '{"enable_thinking": false}'`: Qwen3 の「考えてから答える」動作を止める。付けないと結果が遅くなり、予算の 1 秒に入らない

### 3. 起動コマンドを確かめる

Dictate は、オンにしたときに接続できなければ `formatter.startCommand` のコマンドでサーバを起動する。
既定値が手順 2 と同じコマンドなので、mlx-lm を既定のモデルとポートで使うなら、何も書かなくてよい。

別のモデルやポートにするときは、メニューバーのマイクのアイコンから「設定ファイルを開く」を選び、`formatter.startCommand` を書き換える。

```json
"formatter" : {
  "enabled" : true,
  "startCommand" : "mlx_lm.server --model mlx-community/Qwen3-8B-4bit --port 8124 --chat-template-args '{\"enable_thinking\": false}'",
  ...
}
```

JSON の文字列の中なので、`"` は `\"` と書く。
自動で起動してほしくなければ `""`（空文字）にする。`null` は既定のコマンドの意味になる。
保存したら、メニューの「設定と辞書を再読み込み」を選ぶ。

### 4. オンにする

メニューの「LLM で整える（フィラーと句読点）」をオンにする。
接続できなければ、Dictate が `startCommand` のコマンドでサーバを起動し、「整形サーバを起動しています」と知らせる。
待ち受けが開いた時点で「接続できました。モデルを読み込んでいます」と出る（手元では 3 秒）。
mlx-lm は待ち受けを先に開き、モデルは背景で読み込む。読み込みが終わるまで Dictate は整形を試みず、発話はそのまま入る。
初回でモデルのダウンロードが残っていれば、終わるまで同じ状態が続く。進み具合はメニューの「整形サーバのログを開く」で見られる。
読み込みが終わると「整形の準備ができました」と出て、次の発話から整形が効く。

メニューを開くと「整形: 有効（接続可）」と出る。
「サーバを起動中 N 秒」「モデルを読み込み中 N 秒」の間は、まだ待っている。

サーバは、「LLM で整える」をオフにしたときと、Dictate を終了したときに、Dictate が止める。
Dictate が強制終了されたときも、サーバ側が親の消失を見て 1 秒以内に止まる。
Dictate が起動したものだけを止め、自分で立てたサーバには触らない。

mlx-lm が入っていなければ、起動せずに「mlx-lm が入っていません。brew install mlx-lm を実行してから」と知らせる。
`startCommand` を `""` にした場合は、サーバを自分で起動してからオンにする。
接続できないときは、その旨と対処をトーストで知らせ、メニューに「ローカル LLM の手引きを開く」が出る。

## 動いているかを確かめる

話した後の挿入が、フィラーの消えた文になっていれば動いている。
履歴（`~/Library/Application Support/Dictate/history.jsonl`）には、整形前の文、整形後の文、採用の可否、かかった時間が残る。

## モデルをどう選んだか

既定を Qwen3-8B の 4bit 版にしたのは、「キーを離してから 1 秒以内に挿入する」という予算に入る中で、試した範囲で最も大きいモデルだったからである。
計測は作者 1 人の声と 1 台の Mac（Apple Silicon、メモリ 48 GB、macOS 27）によるもので、整形の 4 文（Slack 風、メール風、メモ風、介護記録風）に同じプロンプトを与えた。

| モデル | 整形の所要（4 文） | 分かったこと |
|---|---|---|
| Qwen3.8-27B 6bit（vMLX） | 2.8〜7.1 秒 | 整形の品質は使える水準。ただし言い直しを半分だけ反映し、「150」に発話にない「ml」を補った。音声入力には遅すぎる |
| Qwen3-8B 4bit（mlx_lm.server） | 0.36〜0.94 秒（温まった状態。初回は 0.6〜1.3 秒） | 予算に入る。ただし「箇条書きにして」の指示を無視し、文の一部を落とすことがあり、「150」に「ミリリットル」を補った |
| Qwen3-1.7B 4bit、Qwen3-0.6B 4bit | （整形では未計測） | 別の用途（辞書の候補を選ぶ採点器）で測った。実機の 99 発話で、8B は直す 7 件・壊す 0 件、1.7B は直す 1 件・壊す 0 件、0.6B は直す 1 件・壊す 2 件。小さくするほど判断が落ちる |
| Qwen3.5-4B、Gemma 4 E4B | 未計測 | 8B より指示に従うという報告はあるが、この用途では測っていない |

27B は品質が良くても遅延で落ち、8B は遅延に入っても指示追従と補完に問題が残った。
この結果から、LLM の役割を「フィラーの削除と句読点」に絞り、編集の指示はコードで扱い、数値は印に置き換えて LLM に見せない設計にした。
8B のままでも、検証を通った出力だけを使うので、文が勝手に書き換わることはない。

8B より小さいモデルに替えると速くなるが、採点器での結果から見て、フィラーの判断も落ちると考えている。
8B より大きいモデルに替えるなら、`formatter.budgetSeconds` を延ばす。
予算を超えた結果は挿入されず、履歴にだけ残る。

## 別のサーバを使う

OpenAI 互換の API（`/v1/chat/completions`）を持つサーバなら、`config.json` の `formatter.endpoint` と `formatter.model` を変えれば使えるはずである。
Ollama や LM Studio がこれに当たるが、作者は試していない。
`enableThinking` の指定は Qwen3 向けで、他のモデルでは無視されるか、エラーになる。

## 困ったとき

| 症状 | 見るところ |
|---|---|
| 「整形サーバを起動できませんでした」と出る | メニューの「整形サーバのログを開く」。`command not found` なら、`startCommand` を `which mlx_lm.server` のフルパスにする（Dictate はログインシェルの PATH を使うが、`.zshrc` だけで PATH を足している環境では見つからない）。直したら「設定と辞書を再読み込み」の後に「整形サーバを起動」を選ぶ |
| 「待ち受けが 60 秒たっても開きません」と出る | サーバは動いているのに Dictate が見ているポートと違う。`startCommand` の `--port` と `formatter.endpoint` を揃え、「整形サーバを起動」を選ぶ |
| 「接続できました。モデルを読み込んでいます」のまま長い | ダウンロードの途中。ログに進み具合が出る。終わると「整形の準備ができました」と出る |
| 「mlx-lm が入っていません」と出る | `brew install mlx-lm` を実行してから、もう一度オンにする。入れてあるのに出るなら、`.zshrc` だけで PATH を足している環境なので、`startCommand` を `which mlx_lm.server` のフルパスにする |
| 「サーバが動作中に終了」と出る | サーバが落ちた。ログの末尾に理由が出る。メモリ不足が多い。「整形サーバを起動」で起動し直せる |
| `Address already in use` | 同じポートで別のサーバが動いている。手で立てたものが残っていれば、そのターミナルで止める |
| 「この Mac では整形に N 秒かかり、予算に入りません」と出る | 温めた直後に 1 文を測った結果。`budgetSeconds` を N より少し長くする（キーを離してから入るまでがその分遅れる）か、小さいモデル（`--model mlx-community/Qwen3-4B-4bit` など。未計測）に替えるか、整形をオフにする。メニューの「整形」の行にも所要が出る |
| 整形が採用されず「整形前の文を挿入しました」が続く | 時間切れなら `budgetSeconds` を延ばす。検証の棄却なら、モデルがフィラーと句読点以外を書き換えている。履歴（`history.jsonl` の `"type": "format"` の行）に秒数と整形後の文が残る |
| Mac が重い | サーバが約 4.6 GB を使っている。使わないときは「LLM で整える」をオフにすると、Dictate が止める |
